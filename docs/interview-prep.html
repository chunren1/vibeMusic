90 秒项目开场白 （背下来）

💬 面试话术 「我独立开发了一个全栈音乐平台 vibeMusic，我主要负责前端部分。技术栈是 Vue3 + Vite + Pinia + Vue Router + Axios。

它做了三件比较有深度的事：
第一，播放器状态管理——全局单例 Audio，队列、音量、播放进度都持久化到 localStorage，还支持后台播放和系统媒体控制；

JS 高频题

6 题全覆盖
Q1 · 闭包是什么？你项目哪用到了？

答案：闭包 = 函数 + 它创建时所在作用域的引用。内层函数即使在外层函数执行完后，依然能访问外层变量，实现变量私有化、柯里化、防抖节流。

💬 项目案例（useToast.js 单例） 
const message = ref('')
let timer = null          // 闭包捕获的环境
export function useToast() {
  function toast(msg, t='info', duration=3000) {
    clearTimeout(timer)   // 闭包访问外层 timer
    timer = setTimeout(() => { show.value = false }, duration)
  }
  return { message, toast }
}
追问预备「闭包的坑」：内存泄漏——闭包持有外层引用不释放。useClickOutside 在 onUnmounted 里 removeEventListener 就是主动释放。
Q2 · var / let / const 区别？什么是暂时性死区？
varletconst
作用域函数作用域块级作用域块级作用域
变量提升✅ 提升并初始化为 undefined✅ 提升但不初始化同 let
重复声明✅ 允许❌ 报错❌ 报错
赋值可改可改引用不可改（对象属性可改）

暂时性死区（TDZ）：let/const 声明语句之前访问变量会报 ReferenceError——提升但不初始化，这段不可访问区间叫 TDZ。

💬 加分点「项目里 90% 以上用 const，语义明确——看到 const 就知道引用不会变。」
Q3 · 事件循环：输出顺序题 
console.log(1)                              // 同步
setTimeout(() => console.log(2), 0)     // 宏任务
Promise.resolve().then(() => console.log(3)) // 微任务
console.log(4)                              // 同步

答案：1 → 4 → 3 → 2

规则：① 先跑完全部同步代码 → ② 清空微任务队列（Promise.then / queueMicrotask）→ ③ 每执行一个宏任务后再清一次微任务 → 循环。

💬 项目案例（虚拟滚动 rAF 节流） 
function onScroll(e) {
  if (!ticking) {              // 一帧只执行一次
    requestAnimationFrame(() => {  // 渲染前回调
      scrollTop.value = e.target.scrollTop
      ticking = false
    })
    ticking = true
  }
}
Q4 · Promise 与异步编程（含竞态）
  • 三态：pending → fulfilled / rejected，状态一旦改变不可逆
  • then 返回新 Promise 支持链式；async/await 是语法糖
  • Promise.all 全成则成 / allSettled 等全部结束 / race 先到先得
💬 项目案例（AbortController 防搜索竞态） 
let controller = null
async function search(kw) {
  controller?.abort()          // 取消上一次请求
  controller = new AbortController()
  try {
    const res = await api.search(kw, { signal: controller.signal })
  } catch (e) {
    if (e.name === 'AbortError') return  // 忽略被取消的旧请求
  }
}
追问「为什么不用请求序号比较？」「AbortController 真正取消了网络请求，省带宽和服务端压力；序号比较只是忽略旧结果，请求还是发出去了。」
Q5 · 原型链与继承

答案：每个函数有 prototype；每个对象有 __proto__（标准：Object.getPrototypeOf）。访问属性找不到就沿 __proto__ 向上，直到 Object.prototype → null。class extends 是语法糖。

instanceof 原理：沿实例 __proto__ 链找构造函数 prototype。[] instanceof Object 为 true（Object 在链上）。

手写继承：Child.prototype = Object.create(Parent.prototype)，并修正 constructor 指向。

Q6 · this 绑定四规则
  1. 默认绑定：普通调用 → window（严格模式 undefined）
  2. 隐式绑定：obj.method() → obj
  3. 显式绑定：call / apply / bind
  4. new 绑定：new Fn() → 新对象（优先级最高）

箭头函数没有自己的 this，继承外层作用域（定义时决定）。

💬 加分点「Vue3 Composition API 让我几乎不需要关心 this——数据和方法都是闭包变量直接引用，这也是我更喜欢组合式 API 的原因。」

Vue3 高频题

6 题全覆盖
Q1 · 响应式原理（ref / reactive / Proxy）

答案：Vue3 用 Proxy 实现响应式。拦截 get（收集依赖）/ set（触发依赖）等操作。ref 包装基本类型为 { value }；computed 基于依赖做缓存。

追问「Vue2 缺陷」：defineProperty 只能拦截已有属性，新增/删除属性、数组索引赋值监听不到，需要 $set/$delete。Vue3 Proxy 天然支持，且惰性代理性能更好。
追问「ref vs reactive」：ref 适合单值、解构安全；reactive 适合嵌套对象但解构丢响应式（要 toRefs）。
💬 项目案例（watch 自动持久化） 
watch(queue, debouncedSave, { deep: true })       // 队列变化 → 防抖保存
watch(currentSong, debouncedSave, { deep: true }) // 切歌 → 保存
Q2 · 生命周期

顺序：setup（= beforeCreate + created）→ onBeforeMount → onMounted → onBeforeUpdate → onUpdated → onBeforeUnmount → onUnmounted。另有 onActivated / onDeactivated（keep-alive）、onErrorCaptured（错误边界）。

铁律：onMounted 绑的监听 / 定时器，onUnmounted 必须成对清理（防内存泄漏）。
💬 项目案例（MBottomPlayer + useVirtualList） 
onMounted(() => {
  window.addEventListener('song-change', updateFaved)
  timeSaver = setInterval(() => store.savePlaybackTime(), 5000)
})
onUnmounted(() => {
  window.removeEventListener('song-change', updateFaved)
  clearInterval(timeSaver)          // ← 清理定时器
  resizeObserver.disconnect()       // ← 断开观察器
})

Q4 · 路由守卫（双端分流）

答案：beforeEach（全局前置）/ beforeResolve / afterEach；路由独享 beforeEnter；组件内 onBeforeRouteUpdate。next() 放行 / next(false) 取消 / next(path) 重定向。

💬 项目案例（双端路由自动分流） 
router.beforeEach((to, from, next) => {
  if (checkMobile()) {                 // 移动设备 → 强制 /m 路由
    const mobilePath = to.meta?.mobilePath || '/m' + to.path
    if (!to.path.startsWith('/m')) return next(mobilePath)
  }
  next()
})

网络与工程化

6 题全覆盖 · 项目最有深度部分
Q1 · JWT 鉴权流程（王牌题）

答案：JWT 三部分 Header.Payload.Signature。Payload 放用户信息 + 过期时间，Signature 用密钥签名——防篡改但不加密（base64 明文，不能放敏感信息）。

流程：登录 → 签发 access（15min）+ refresh（7d）→ 请求带 Authorization: Bearer → 验签放行 → access 过期用 refresh 换新。

追问「为什么双 Token」：access 短命缩小被盗窗口；refresh 只用于换新不走业务接口，可服务端撤销。
追问「JWT vs Session」：Session 服务端存状态、可踢人、多实例要共享存储；JWT 无状态天然适合分布式，缺点是不能主动失效（要黑名单）。
💬 项目话术「我的项目用 JWT 双 Token + httpOnly Cookie 双通道：access 放内存，refresh 放 httpOnly Cookie——XSS 读不到 Cookie，CSRF 拿不到内存 token，两边都防。」
Q2 · 为什么 JWT 不放 localStorage？（安全考点）

答案：localStorage 有 XSS 风险——脚本注入后 localStorage.getItem('token') 直接偷走。httpOnly Cookie 脚本读不到，只能浏览器自动携带。trade-off：Cookie 天然带 CSRF 风险，需 SameSite + 校验 Origin 防护。

💬 项目案例（会话恢复） 
// 不存 localStorage，启动时调 /auth/me —— 浏览器自动带 httpOnly Cookie
async function tryRestoreSession() {
  const res = await getMe()   // 浏览器自动带 Cookie → 后端识别身份
  if (res.code === 200 && res.data) { /* 恢复用户信息 */ }
}
Q3 · HTTP 状态码 + 401 vs 403
  • 2xx：200 / 201 / 204
  • 3xx：301 永久重定向 / 302 临时 / 304 缓存
  • 4xx：400 参数错 / 401 未认证 / 403 无权限 / 404 / 429 限流
  • 5xx：500 内部错误 / 502 网关错 / 503 不可用 / 504 超时
辨析：401 =「你是谁？」没带/无效凭证；403 =「我知道你是谁，但没权限」。项目里 handleUnauthorized 对 401/403 统一处理。
GET vs POST：GET 读、参数在 URL（可缓存可分享）；POST 写、参数在 body。敏感操作必须 POST。
Q4 · 跨域 CORS

答案：协议/域名/端口任一不同即跨域。解决：① CORS（服务端 Access-Control-Allow-Origin；带自定义头触发预检请求）② 代理（Vite proxy / Nginx 反代）③ JSONP（仅 GET，过时）。

💬 项目话术（分层解决）「开发时 Vite proxy 转发 /api，生产时 Nginx 反代 → 前端始终同源访问，最干净。App 跨域场景 axios withCredentials + 后端 CORS 允许。这让我理解'为什么企业项目要配网关层'——不止跨域，还能统一鉴权限流。」

Q：讲讲你的项目架构？

✅ 参考话术「浏览器同一时间只能真正出声一个 audio 元素，切歌时新建不关旧的会串音、泄漏。我用模块级单例 window.vibeAudio 全站共享，切歌只替换 src。」

Q：刷新页面播放状态怎么恢复？

✅ 参考话术「三处配合：watch 监听队列/当前歌曲 300ms 防抖写 localStorage；beforeunload 时 flushSave 强制落盘存进度；页面加载后 restorePlayback() 恢复队列并重设 audio src。」

Q：你遇到过什么难点？（必问，STAR 结构）

✅ 参考话术 · 收藏状态不同步 S：做移动端底部播放条时，切歌后收藏「红心」状态不同步。
T：底部播放条、播放页、歌词页三个组件都要实时同步收藏态。
A：player store 切歌时派发 song-change 自定义事件，三个组件各自监听并查收藏状态；onUnmounted 移除监听防泄漏。
R：状态 100% 同步，机制复用到歌词切换。让我理解了：全局共享用状态（Pinia），事件驱动用事件，两者互补。

防抖节流补充（必考）：防抖=停止触发后 delay 才执行，重复触发重置计时器 → 搜索输入、resize（项目：debouncedSave 300ms）；节流=固定间隔最多执行一次 → 滚动、拖拽（项目：ticking + rAF）。一句话：防抖等安静，节流限频率。
