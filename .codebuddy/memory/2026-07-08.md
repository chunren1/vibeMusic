## 修复：最小化窗口时页面反复重新打开

**根因**：三个问题叠加
1. **App.vue `onResize`（主因）**：最小化时 `window.innerWidth` 变为 0，`checkDevice()` 返回 `true`（<768），导致 `isMobile` 切换。`v-if`/`v-else` 销毁重建整个 `RouterView`，表现为"页面重新打开"。
2. **MHomeView.vue**：`fullscreenchange` 监听器在 `<script setup>` 顶层注册且未在 `onUnmounted` 清理；`visibilitychange` 监听器也未清理。keep-alive 下可能累积。
3. **useAudioBackground.js `onAutoPause`**：最小化时浏览器暂停 audio，`onAutoPause` 立即调用 `audio.play()`，可能阻止/延迟浏览器完成最小化。

**修复**：
- `App.vue`：`onResize` 中 `innerWidth===0` 时跳过布局切换；添加 300ms 去抖；添加 `onUnmounted` 清理
- `MHomeView.vue`：将匿名监听器改为命名函数引用，在 `onUnmounted` 中 `removeEventListener`
- `useAudioBackground.js`：`onAutoPause` 首次重试增加 500ms 延迟，给浏览器最小化动画足够时间完成

前端 Vite 热更新，无需重启。

## cpolar 内网穿透登录 403 修复 (23:00)

**问题**：通过 cpolar 隧道域名访问时，登录返回 403，收藏/推荐接口返回 401。

**根因**：
1. `CorsConfig.java` CORS 白名单默认值只有 `localhost:5173,4173`，cpolar 域名不在其中
2. 浏览器发 OPTIONS 预检 → Spring DefaultCorsProcessor 不匹配来源 → 403
3. `allowCredentials=false` 导致跨域无法携带 Authorization 头

**修复**：
- CorsConfig 开发模式（无 CORS_ORIGINS 环境变量）自动放行 `https://*.cpolar.to`、`https://*.cpolar.cn` 等隧道域名
- `allowCredentials` 改为 `true`
- 用户需重启后端服务生效

## 本地开发环境变量 + 中间件连通性全面修复 (23:06)

**问题**：本地直接运行后端（非 Docker）时，多个服务无法连接。

**排查结果**：
1. DB_PASSWORD / REDIS_PASSWORD：`application-dev.yml` 无默认值，本地无系统环境变量 → 后端连不上 MySQL / Redis
2. Redis 端口 6379：docker-compose 注释掉了端口映射 → 宿主机后端无法连接
3. CORS：cpolar 域名 `.top` 未加入白名单（已修复）
4. Docker Compose `deploy.resources`：Swarm 语法 → 需 `--compatibility`

**修复**：
- `application-dev.yml`：DB_PASSWORD 和 REDIS_PASSWORD 加默认值
- `docker-compose.yml`：取消注释 Redis `6379:6379` 端口映射
- `CorsConfig.java`：补上 `*.cpolar.top`，allowCredentials=true
- `package.json`：所有 `docker compose up` 命令加 `--compatibility` 标志
